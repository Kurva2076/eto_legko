# Adrobot — создатель и редактор кампаний Keitaro

Тестовое задание: обёртка над Keitaro Admin API.

- **Бэкенд:** FastAPI + SQLAlchemy 2 + Alembic (SQLite по умолчанию), клиент на httpx
- **Фронтенд:** Vue 3 + Vite

## Что умеет

1. **Создание кампании** (название, гео, оффер с автокомплитом). Создаются:
   - кампания с доменом, группой и источником (берутся из API; по умолчанию — id 1813 / 10332 / 836, если их нет — первый элемент справочника);
   - поток 1 (`regular`, `redirect`): страна(ы) из гео → `https://google.com`, фильтр `country` / `accept`;
   - поток 2 (`default`, `landings`): выбранный оффер, доля 100%.
   - Гео можно указать списком через запятую (`MX,AU,RO`). Если создание потоков не удалось, кампания удаляется — «полусобранных» не остаётся.
   - Созданная кампания вместе с потоками сразу сохраняется в БД и доступна в редакторе.
2. **Редактор кампании.** Работает через нашу БД: всё, что вы видите и меняете, лежит в БД, а в Keitaro уходит только по явной команде.
   - **Стянуть потоки (streams) с Keitaro** — единственная кнопка, которая читает кампанию и потоки из Keitaro и записывает их в БД. Локальные неотправленные изменения при этом перезаписываются (перед этим будет предупреждение).
   - **Потоки.** Показываются все потоки кампании: сначала потоки с офферами (название потока, офферы, доли), затем потоки без офферов (одной строкой). Под каждым потоком есть поле добавления оффера в этот поток.
   - **Закрепление долей (📌).** Закреплённая доля не пересчитывается: при добавлении, удалении и восстановлении офферов, а также при «Распределить поровну» остаток до 100% делится только между незакреплёнными офферами (остаток от деления раздаётся первым: 3 оффера → 34/33/33).
   - **Удаление офферов.** «×» не стирает оффер, а помечает его как `REMOVED` (серая строка в конце списка). У такой строки две кнопки: «Восстановить» и «Удалить полностью» (стирает запись из БД).
   - **Локальные изменения.** Добавление, удаление, восстановление, закрепление и правка долей пишутся только в БД. Поток с неотправленными изменениями подсвечен, изменённые офферы помечены (`новый`, `доля изменена`, `REMOVED`).
   - **Отправка.** У изменённого потока появляются «Отправить изменения в Keitaro» и «Отменить изменения» (откат к состоянию последней синхронизации). Над потоками есть кнопка «Отправить изменения со всех потоков».
   - При отправке состав офферов потока заменяется целиком (`PUT /streams/{id}`): офферы `REMOVED` в Keitaro не попадают. Сумма долей в потоке с офферами должна быть ровно 100% — иначе отправка будет отклонена.
   - Если добавить оффер в поток без офферов (например, `redirect`), локально он становится потоком типа `landings`; в Keitaro схема меняется только при отправке, а «Отменить изменения» возвращает прежнюю.
   - Список кампаний и каталог офферов (для автокомплита) тоже берутся из БД. Список кампаний загружается из Keitaro кнопкой «Обновить список», каталог офферов — один раз при первом поиске и затем при каждом «Стянуть потоки».

## Настройка

Создайте `.env` в корне проекта (см. `.env.example`):

```
KEITARO_API_KEY=<ваш ключ с кнопки «API ключ» в админке стенда>
KEITARO_URL=https://keitaro-for-tests.etolegko.com/admin_api/v1
```

`KEITARO_URL` можно указать и без суффикса `/admin_api/v1` — он будет добавлен автоматически.

Необязательные переменные: `DATABASE_URL` (по умолчанию `sqlite:///backend/adrobot.db`), `DEFAULT_DOMAIN_ID`, `DEFAULT_GROUP_ID`, `DEFAULT_SOURCE_ID`.

## Запуск бэкенда

### Linux

```bash
cd backend
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

# миграции
alembic upgrade head

# сервер
uvicorn app.main:app --reload --port 8000
```

### Windows

```bash
cd backend
py -m venv .venv
Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
.venv\Scripts\Activate.ps1
pip install -r requirements.txt

# миграции
alembic upgrade head

# сервер
uvicorn app.main:app --reload --port 8000
```

Если PowerShell пишет `running scripts is disabled`, выполните один раз используйте cmd и активируйте окружение командой `.venv\Scripts\activate.bat`.

Swagger: http://127.0.0.1:8000/docs

## Запуск фронтенда

```bash
cd frontend
npm install
npm run dev
```

Откройте http://localhost:5173 (запросы `/api` проксируются на бэкенд `127.0.0.1:8000`).

## API бэкенда

`stream_id` во всех путях — ID потока в Keitaro, `campaign_id` — ID кампании в Keitaro.
Методы, помеченные **Keitaro**, обращаются к Keitaro, остальные работают только с БД.
Все методы потоков возвращают обновлённую кампанию (как `GET /api/campaigns/{id}`).

| Метод | Путь | Описание |
|---|---|---|
| GET | `/api/meta` | домен, группа, источник по умолчанию (**Keitaro**) |
| GET | `/api/offers?q=` | поиск офферов по каталогу в БД (пустой каталог один раз грузится из **Keitaro**) |
| GET | `/api/campaigns` | список кампаний из БД |
| POST | `/api/campaigns/sync` | загрузить список кампаний из Keitaro в БД (**Keitaro**) |
| POST | `/api/campaigns` | создать кампанию `{name, geo, offer_id}` (**Keitaro**) |
| GET | `/api/campaigns/{campaign_id}` | кампания с потоками и офферами из БД |
| POST | `/api/campaigns/{campaign_id}/pull` | стянуть кампанию, потоки и офферы из Keitaro в БД (**Keitaro**) |
| POST | `/api/campaigns/{campaign_id}/push` | отправить изменения всех потоков в Keitaro (**Keitaro**) |
| POST | `/api/streams/{stream_id}/push` | отправить изменения потока в Keitaro (**Keitaro**) |
| POST | `/api/streams/{stream_id}/cancel` | отменить неотправленные изменения потока |
| POST | `/api/streams/{stream_id}/offers` | добавить оффер `{offer_id}` (если он `REMOVED`, восстанавливает его) |
| DELETE | `/api/streams/{stream_id}/offers/{offer_id}` | пометить оффер как `REMOVED` |
| POST | `/api/streams/{stream_id}/offers/{offer_id}/restore` | восстановить оффер |
| DELETE | `/api/streams/{stream_id}/offers/{offer_id}/purge` | удалить `REMOVED`-оффер из БД полностью |
| PUT | `/api/streams/{stream_id}/offers/{offer_id}/pin` | закрепить / открепить долю `{pinned}` |
| PUT | `/api/streams/{stream_id}/offers/shares` | задать доли `{shares:[{offer_id, share}]}` (сумма = 100) |
| POST | `/api/streams/{stream_id}/offers/equalize` | распределить доли незакреплённых офферов поровну |
| GET | `/api/created` | локальный журнал созданных кампаний (SQLAlchemy) |

## Структура БД

- `campaign_records` — кампании, созданные через «создаватор»;
- `campaigns` — кампании Keitaro в БД (`synced_at` — время последнего стягивания потоков);
- `streams` — потоки кампаний; `synced_offers` и `synced_schema` хранят состояние потока в Keitaro на момент последней синхронизации, с ними сравнивается локальное состояние (так находятся неотправленные изменения);
- `stream_offers` — офферы в потоках: доля, закрепление (`pinned`), статус `active` / `removed`;
- `offers` — каталог офферов Keitaro для автокомплита;
- `offer_changes` — журнал действий с офферами (добавление, удаление, восстановление, закрепление, доли, отправка, отмена).

Запросы к Keitaro видны в разделе «Журнал» тренировочной админки.
